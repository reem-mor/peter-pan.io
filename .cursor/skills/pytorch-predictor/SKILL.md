# PyTorch Predictor — ML/DL Rules

The Predictor is the crosswalk of the course's Image Analyser (10% of grade).
Same learning objectives, incident domain: transfer learning, 6 classes,
confidence handling, reported test accuracy, .pth deliverable.

## Model
- 6 output classes — names come from `contracts.py`, never hardcoded strings
  scattered in training code. One constants import, used everywhere.
- Transfer learning: pretrained backbone frozen, replaced head fine-tuned.
  Document WHICH backbone and WHY in the training script docstring.
- Confidence: softmax max below threshold (start 0.6, tune on val set) →
  return `uncertain`, never a forced class. The threshold is a named constant
  with a comment stating the val-set numbers that justified it.

## Data
- Synthetic, demo-scale, generated by a committed script — the dataset must
  be reproducible from the repo alone (seeded). Minimum 200 labeled samples,
  stratified 70/15/15 train/val/test split, split by seed not by hand.
- Class balance: report per-class counts. If imbalanced, weighted loss —
  documented, not silent.

## Training script requirements (rubric deliverables)
- `train.py` runs end-to-end with one command, seeds everything
  (`torch.manual_seed`, numpy, random), saves `predictor.pth` + a
  `metrics.json` with: test accuracy (target >75%), per-class precision/recall,
  confusion matrix, threshold used.
- Log every epoch: train loss, val loss, val accuracy. Stop criteria stated
  (fixed epochs or early stopping — pick one, say which).
- No notebook-only training. A notebook may exist for exploration, but the
  deliverable is the script.

## Serving
- Model loads once at service startup (lifespan), eval mode, `torch.no_grad()`
  on inference. CPU inference is fine on t3.large — do not add GPU code paths
  the demo box can't run.
- The service returns `{incident_class, confidence}` exactly — schema in
  contracts.py wins over anything in this file.

## Honesty rules (Karpathy)
- Report the real accuracy, including if it's below 75% — then say what you'd
  try next. Never cherry-pick a lucky seed.
- If the synthetic data makes the task trivially easy (accuracy ~100%), say so
  in metrics.json notes — a lecturer will spot it, better you spot it first.
